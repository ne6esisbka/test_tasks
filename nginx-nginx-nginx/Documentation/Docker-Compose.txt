================================================================================
ДОКУМЕНТАЦИЯ КОМПОНЕНТА: ОРКЕСТРАЦИЯ DOCKER COMPOSE
================================================================================

1. ШАБЛОНИЗАЦИЯ И СВЯЗНОСТЬ (YAML Anchors)
--------------------------------------------------------------------------------
Для исключения дублирования конфигурации воркеров Nginx применен паттерн DRY 
через YAML-якоря (&nginx-common) и алиасы (<<: *nginx-common). 
Динамическая связность каскада задается через переменные окружения (environment):
- nginx1 пересылает трафик на nginx2:80
- nginx2 пересылает трафик на nginx3:80
- nginx3 пересылает трафик на app:8000

Это симулирует каскадное прохождение запроса (цепочку) при попадании на первый узел.

2. ПРОДАКШЕН-ОГРАНИЧЕНИЯ (Resource Management)
--------------------------------------------------------------------------------
Каждый сервис изолирован на уровне ядра Linux (cgroups) с помощью директив:
- cpus: '0.5' — защита от утилизации процессора хоста при зацикливании кода.
- memory: 128M — жесткий лимит ОЗУ, предотвращающий деградацию системы при утечках.

3. УПРАВЛЕНИЕ ЛОГАМИ (Log Rotation)
--------------------------------------------------------------------------------
Для защиты дискового пространства хоста от переполнения (Disk Full) для всех 
контейнеров переопределен стандартный лог-драйвер json-file:
- max-size: "10m" (максимальный размер одного файла лога).
- max-file: "3" (глубина ротации).
Суммарный объем логов всего стенда физически не может превысить 150 МБ.
