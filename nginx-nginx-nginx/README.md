Архитектурный стенд для демонстрации динамической маршрутизации запросов через цепочку обратных прокси-серверов (Reverse Proxy) с гарантированной защитой от подмены IP-адресов (**IP Spoofing**).

---

## 🏗️ Архитектура системы

Стенд разворачивает изолированную инфраструктуру внутри Docker-сети `xffnet` (`172.28.0.0/24`):

[Пользователь] (IP: 172.28.0.1)│
▼ 
(Попытка подмены: XFF: 9.9.9.9)
┌───────────┐
│  nginx1   │  ──► Проверка источника. IP не входит в 172.28.0.0/24.
└───────────┘      Фейковый заголовок СБРАСЫВАЕТСЯ.│▼ (XFF: 172.28.0.1)
┌───────────┐
│  nginx3   │  ──► Источник (nginx1) доверенный. Цепочка сохраняется.
└───────────┘      Добавляется IP текущего узла.│▼ (XFF: 172.28.0.1, 172.28.0.11)
┌───────────┐
│    app    │  ──► Python-бэкенд получает валидный лог прохождения трафика.
└───────────┘

### Ключевые компоненты:
* **`app`**: Python Mock-сервер. Работает в режиме **Non-Root** (UID 1000) и **Read-Only FS** [1].
* **`nginx1, nginx2, nginx3`**: Прокси-серверы с модулем `ngx_http_realip_module` для рекурсивного анализа цепочки XFF.
* **Динамический роутинг**: Реализован через встроенные карты Nginx (`map`) на основе заголовка `X-Next-Proxy`.

## ⚡ Быстрый старт

### 1. Развертывание стенда
```bash
docker compose up -d --build
```

### 2. Верификация статуса компонентов
```bash
docker compose ps
```
*Все 4 контейнера должны находиться в статусе `running (healthy)`.*

## 🧪 Протокол автоматизированного тестирования (curl)


| № | Сценарий тестирования | Команда проверки (CLI) | Ожидаемый результат |
|---|---|---|---|
| **1** | **Прямой запрос**<br>`User -> Nginx1 -> App` | `curl -s http://localhost:8081/` | `Полученный X-Forwarded-For: 172.28.0.1` |
| **2** | **Защита от Spoofing**<br>`User[Fake XFF] -> Nginx1 -> App` | `curl -s -H "X-Forwarded-For: 9.9.9.9" http://localhost:8081/` | `Полученный X-Forwarded-For: 172.28.0.1`<br>*(Фейк 9.9.9.9 стерт)* |
| **3** | **Сложная цепочка**<br>`User -> Nginx1 -> Nginx3 -> Nginx2 -> App` | `docker exec -it nginx1 curl -s -H "X-Forwarded-For: 172.28.0.1" -H "X-Next-Proxy: nginx2" http://nginx3/` | `Полученный X-Forwarded-For: 172.28.0.1, 172.28.0.11, 172.28.0.13` |
| **4** | **Комплексная защита**<br>`User[Fake] -> Nginx-цепочка -> App` | `docker exec -it nginx1 curl -s -H "X-Forwarded-For: 9.9.9.9, 172.28.0.1" -H "X-Next-Proxy: nginx2" http://nginx3/` | `Полученный X-Forwarded-For: 172.28.0.1, 172.28.0.11, 172.28.0.13`<br>*(Мусор отброшен)* |

## 🛠️ Ресурсные ограничения (Production-Ready)

Для обеспечения стабильности хост-системы к контейнерам применены следующие лимиты:
* **CPU Limit**: Не более `0.5` ядра на каждый контейнер.
* **RAM Limit**: Жесткий лимит `128MB` оперативной памяти на сервис.
* **Log Rotation**: Максимальный размер лог-файла — `10MB`, ротация — до `3` файлов (макс. `30MB` на контейнер).
