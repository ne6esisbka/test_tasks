1. СХЕМА ОБРАБОТКИ ЗАГОЛОВКОВ И ЗАЩИТЫ ОТ СПУФИНГА
--------------------------------------------------------------------------------

[Пользователь] (IP: 9.9.9.9) 
      │ 
      ▼ (Попытка подмены: XFF: 1.1.1.1)
┌───────────┐
│    lb     │ ──► Тупой балансировщик (172.28.0.10). Игнорирует XFF.
└───────────┘     Фиксирует физический IP клиента в заголовке X-Real-IP: 9.9.9.9.
      │
      ▼ (Запрос улетает по Round-Robin, например на nginx1)
┌───────────┐
│  nginx1   │ ──► Проверяет физический IP отправителя ($realip_remote_addr)
└───────────┘       • Отправитель — балансировщик lb (172.28.0.10).
                    • Фейковый XFF пользователя (1.1.1.1) ПОЛНОСТЬЮ СБРАСЫВАЕТСЯ.
                    • Формируется честный XFF из X-Real-IP: "9.9.9.9".
      │
      ▼ (Запрос передается дальше по цепочке NEXT_UPSTREAM)
┌───────────┐
│  nginx2   │ ──► Проверяет физический IP отправителя ($realip_remote_addr)
└───────────┘       • Отправитель — сосед nginx1 (172.28.0.11).
                    • Включается ветка default: существующий XFF сохраняется.
                    • В конец цепочки дописывается IP предыдущего прокси.
                    • Формируется цепочка XFF: "9.9.9.9, 172.28.0.11".
      │
      ▼
┌───────────┐
│    app    │ ──► Приложение получает гарантированно валидную цепочку IP.
└───────────┘


2. БАЛАНСИРОВЩИК (lb.conf)
--------------------------------------------------------------------------------
Выполняет роль внешней "тупой" точки входа (Dumb Load Balancer).
- Алгоритм: Round-Robin (равномерное распределение по воркерам nginx1-3).
- Задача: Записать физический IP-адрес сетевого подключения хоста во внутренний 
  заголовок X-Real-IP (proxy_set_header X-Real-IP $remote_addr;). Это полностью 
  исключает возможность влияния пользователя на определение его первоначального IP.


3. ПРОКСИ-ВОРКЕРЫ (proxy.conf.template)
--------------------------------------------------------------------------------
Используют механизм встроенных шаблонов Nginx. При старте переменная $NEXT_UPSTREAM 
подставляется в директиву proxy_pass.

- Директива set_real_ip_from 172.28.0.10:
  Прокси-серверы объявляют балансировщик доверенным узлом для чтения X-Real-IP.

- Блок маппинга (map $realip_remote_addr $validated_xff):
  Ключевой элемент защиты от спуфинга и построения цепочки. Переменная 
  $realip_remote_addr хранит физический IP отправителя пакета.
  
  * ЕСЛИ $realip_remote_addr == 172.28.0.10 (запрос пришел от LB):
    Nginx понимает, что это ВХОД в систему. Он полностью игнорирует и стирает 
    входящий X-Forwarded-For пользователя и записывает туда ТОЛЬКО честный 
    адрес из X-Real-IP. Спуфинг ликвидирован.
    
  * ЕСЛИ $realip_remote_addr == Любой другой IP (запрос идет внутри сети Docker):
    Nginx понимает, что запрос транзитный. Он берет накопленный заголовок со 
    предыдущих шагов и дописывает туда IP предыдущего прокси через переменную 
    $proxy_add_x_forwarded_for.
