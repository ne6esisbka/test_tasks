Документация NGINX: 
Конфигурация Nginx для динамического проксирования и защиты X-Forwarded-ForДанная конфигурация разработана для построения
 отказоустойчивой цепочки обратных прокси-серверов (Reverse Proxy) внутри изолированной сети Docker. Она решает
  две ключевые задачи: динамическую маршрутизацию запросов между компонентами стенда и защиту от подмены
   IP-адресов (IP Spoofing).
   Архитектурная схема обработки заголовка
   
[Пользователь] (IP: 9.9.9.9) 
      │ 
      ▼ (Попытка подмены: XFF: 1.1.1.1)
┌───────────┐
│  nginx1   │ ──► Сверяет IP источника с доверенной подсетью 172.28.0.0/24
└───────────┘       • Источник (9.9.9.9) НЕ входит в подсеть.
      │             • Фейковый XFF сбрасывается.
      ▼             • Формируется честный XFF:
┌───────────┐
│  nginx2   │ ──► Сверяет IP источника (nginx1: 172.28.0.11)
└───────────┘       • Источник входит в доверенную подсеть.
      │             • Существующий XFF сохраняется, в конец пишется IP прокси.
      ▼             • Формируется цепочка XFF:
┌───────────┐
│    app    │ ──► Приложение получает гарантированно валидную цепочку IP.
└───────────┘

Подробный разбор директив конфигурации:

1. Блок events (Управление соединениями)
events { 
    worker_connections 1024; 
}

worker_connections 1024: Задает максимальное количество одновременных сетевых соединений (файловых дескрипторов),
 которое может открыть один рабочий процесс (worker). Поскольку Nginx работает в режиме обратного прокси,
  на один клиентский запрос тратится 2 соединения (Клиент ◄► Nginx и Nginx ◄► Бэкенд). Данный лимит позволяет
   обрабатывать до 512 конкурентных запросов на один воркер.

2. Блок real_ip (Безопасность и валидация цепочки)nginxset_real_ip_from  172.28.0.0/24;
real_ip_header    X-Forwarded-For;
real_ip_recursive on;
Используйте код с осторожностью.set_real_ip_from: Определяет границы доверенной зоны (внутренней подсети Docker).
 Запросы, приходящие из этого диапазона, признаются легитимными прокси-запросами.real_ip_header:
  Инструктирует Nginx анализировать заголовок X-Forwarded-For для поиска первоначального адреса клиента,
   если запрос пришел из доверенной зоны.real_ip_recursive on: Включает рекурсивный обход цепочки адресов
    в заголовке справа налево. Nginx отбрасывает все внутренние IP-адреса, входящие в set_real_ip_from,
     и фиксирует первый встреченный внешний IP как истинный $remote_addr.Эффект защиты: Если внешний
      злоумышленник передаст поддельный заголовок X-Forwarded-For: 1.1.1.1, Nginx определит, что физический
       IP клиента не входит в доверенную подсеть, и полностью проигнорирует (сотрет) этот заголовок, защищая
        приложение от спуфинга.

3. Блок upstream (Абстракция бэкенда)

upstream backend_app {
    server 172.28.0.100:8000;
}

Создает логический пул серверов с именем backend_app. Это изолирует сетевые параметры приложения от логики проксирования.
 При масштабировании приложения (добавлении новых контейнеров) изменения вносятся только в этот блок.
  По умолчанию используется алгоритм балансировки Round-Robin.

4. Блок map (Динамическая маршрутизация)

map $http_x_next_proxy $target_upstream {
    default $http_x_next_proxy;
    ""      "backend_app";
}

Создает динамическую переменную $target_upstream, значение которой зависит от входящего HTTP-заголовка X-Next-Proxy
 (в переменной Nginx он преобразуется в $http_x_next_proxy).Если заголовок пустой (""), переменная принимает
  значение "backend_app" (запрос идет в приложение).Если в заголовке указано имя (например, nginx2),
   переменная принимает это имя, перенаправляя запрос на следующий прокси-сервер. Это позволяет гибко
    тестировать цепочки любой длины без изменения конфигурации.

5. Блок server и resolver (Служебные настройки)

nginxresolver 127.0.0.11 valid=5s;

127.0.0.11: Системный IP-адрес встроенного DNS-сервера Docker Daemon.Поскольку в директиве proxy_pass
 используется переменная ($target_upstream), Nginx обязан резолвить доменные имена (имена контейнеров)
  на лету в режиме реального времени. Без указания локального резолвера Docker Nginx выдаст ошибку инициализации.
   Параметр valid=5s инвалидирует DNS-кэш каждые 5 секунд для корректной обработки перезапуска контейнеров.

6. Блок location / (Проксирование и заголовки)
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Next-Proxy $http_x_next_proxy;
proxy_pass http://$target_upstream;
proxy_next_upstream error timeout invalid_header http_500 http_502;

proxy_add_x_forwarded_for: Автоматически дополняет заголовок. Она берет очищенный модулем real_ip
 входящий заголовок и добавляет через запятую IP-адрес текущего узла, формируя корректную цепочку
  прохождения трафика.proxy_next_upstream: Повышает отказоустойчивость стенда. Если целевой
   прокси-сервер или бэкенд возвращает сетевую ошибку (500, 502, таймаут), Nginx не возвращает
    ошибку пользователю, а пытается немедленно перенаправить запрос на альтернативный узел,
     если он описан в upstream.
