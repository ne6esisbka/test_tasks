# 🛡️ Dynamic Nginx Proxy Chain & Spoofing Protection Stand

[![Docker Compose](https://shields.io)](https://docker.com)
[![Nginx](https://shields.io)](https://nginx.org)
[![Python](https://shields.io)](https://python.org)

Архитектурный стенд, эмулирующий работу каскада обратных прокси-серверов (Reverse Proxy) с балансировкой нагрузки Round-Robin и сквозной валидацией цепочки `X-Forwarded-For`. 

Проект полностью решает задачу сбора честной цепочки IP-адресов и гарантирует 100% защиту от подмены IP (**IP Spoofing**) со стороны пользователя.

---

## 🏗️ Архитектура сетевых потоков

Трафик внутри изолированной Docker-сети `xffnet` (`172.28.0.0/24`) движется по следующей схеме:

[Внешний Клиент] (Реальный IP: 172.28.0.1, Спуфинг: XFF: 9.9.9.9)│
▼ 
(Порт 8080)┌───────────┐
│    lb     │ ──► Тупой балансировщик. Игнорирует XFF.
└───────────┘     Фиксирует IP клиента в X-Real-IP: 172.28.0.1.│
├───────────────────────┼───────────────────────┐
▼ (Round-Robin)         ▼ (Round-Robin)         ▼ (Round-Robin)
┌───────────┐           ┌───────────┐           ┌───────────┐
│  nginx1   │           │  nginx2   │           │  nginx3   │
└───────────┘           └───────────┘           └───────────┘
     │                         │                       │
     ▼                         ▼                       ▼
[nginx2 -> nginx3 -> app]   [nginx3 -> app]         [app:8000]

### Ключевые механизмы:
1. **Dumb LB (`lb`)**: Эмулирует внешний BGP/Ingress-слой. Передает реальный IP соединения в заголовке `X-Real-IP`.
2. **Шаблонизация (`proxy.conf.template`)**: Все прокси-серверы используют *один и тот же* конфигурационный файл, который динамически адаптируется под переменные окружения `NEXT_UPSTREAM`.
3. **Карта Безопасности (`map`)**: На первом прокси (вход от LB) заголовок `X-Forwarded-For` пользователя **полностью стирается** и перезаписывается. На последующих шагах цепочки — рекурсивно дополняется.

## ⚡ Быстрый старт

1. Разверните инфраструктуру стенда в фоновом режиме:
   ```bash
   docker compose up -d --build
   ```
2. Убедитесь, что все сервисы успешно запустились:
   ```bash
   docker compose ps
   ```

## 🧪 Протокол автоматизированного тестирования
В корень проекта интегрирован автоматический Bash-скрипт тестирования. Для проверки всех сценариев ТЗ выполните:
```bash
chmod +x test_stand.sh
./test_stand.sh
```

### Сводная таблица сценариев ТЗ:

| № | Сценарий проверки | Команда / Скрипт | Ожидаемый результат приложения |
|---|---|---|---|
| **1** | **Прямой/Короткий запрос** | `curl -s http://localhost:8080/` | Наличие IP пользователя (`172.28.0.1`) |
| **2** | **Защита от Spoofing** | `curl -s -H "X-Forwarded-For: 9.9.9.9" http://localhost:8080/` | Фейк `9.9.9.9` **удален**. Выводится только честный IP |
| **3** | **Сбор длинной цепочки** | Автоматически через Round-Robin | Вывод всей цепочки прохождения (например: `172.28.0.1, 172.28.0.11, 172.28.0.12`) |

## 🛠️ Инфраструктурные ограничения (Production-Ready)
Для предотвращения деградации хост-системы к контейнерам применены лимиты:
* **Ресурсы**: Каждый контейнер ограничен `0.5 CPU` и `128MB RAM`.
* **Логирование**: Включена автоматическая ротация логов (макс. 3 файла по 10MB на контейнер).
