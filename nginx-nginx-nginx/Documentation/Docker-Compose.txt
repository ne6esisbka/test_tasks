Документация Docker Compose:
Описание инфраструктуры
Данный конфигурационный файл разворачивает изолированный локальный стенд,
    состоящий из четырех связанных контейнеров, объединенных в общую виртуальную сеть.
    Стенд полностью автономен и оптимизирован для работы в условиях ограниченных ресурсов.

Архитектура и компоненты стенда

1. Сервис приложения (app)
Легковесный бэкенд на базе Python 3.12, развернутый на минималистичной ОС Alpine Linux.
    Принимает HTTP-запросы и выводит заголовки для проверки.
Безопасность: Запускается под специальным не-привилегированным пользователем (UID 1000). 
    Локальная папка с кодом монтируется в режиме «только для чтения», что полностью исключает 
    возможность изменения исходного кода изнутри контейнера.

2. Сервисы проксирования (nginx1, nginx2, nginx3)
Три идентичных сервера Nginx 1.27, выступающих в роли обратных прокси-серверов. Они могут
    принимать внешние запросы от пользователя или передавать их друг другу по цепочке.
Безопасность: Запускаются в стандартном безопасном режиме. Главный процесс управляет портами,
    а все рабочие процессы, обрабатывающие трафик пользователей, автоматически сбрасывают
    привилегии до системного пользователя nginx.

3. Сетевая подсистема (xffnet)
  Назначение: Изолированная виртуальная сеть типа «bridge». Всем контейнерам жестко назначены
   постоянные внутренние IP-адреса. Это необходимо, чтобы сервера Nginx могли однозначно определять,
    пришел ли запрос от доверенного соседа по Docker-сети или от внешнего пользователя.

4. Политики оптимизации и ограничения ресурсов
Для предотвращения деградации хост-машины (компьютера, на котором запускается стенд) ко всем
    сервисам применены строгие лимиты.
Ограничение процессора и памяти (CPU / RAM)
Выделение ядер: Каждому контейнеру разрешено использовать не более 50% мощности одного ядра
    процессора. Это защищает систему от зависания в случае бесконечных циклов в коде.
Выделение памяти: Для каждого сервиса установлен жесткий лимит в 128 Мегабайт оперативной памяти.
    В случае утечки памяти в приложении Docker автоматически перезапустит конкретный контейнер,
    не затронув остальную систему.

5. Ротация и ограничение логов (Logging)Контроль диска: Все контейнеры настроены на использование
    стандартного драйвера логирования с жестким лимитом на размер файлов.
Объем данных: 
Максимальный размер одного файла логов составляет 10 Мегабайт. Система хранит не более 3 архивных файлов 
    для каждого контейнера. Как только лимит превышается, старые логи автоматически затираются.
    Таким образом, весь стенд физически не может занять на жестком диске более 120 Мегабайт логической информации.
